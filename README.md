# ПОС — Преподавательская оценка студентов

Домашняя работа №2 по конструированию программного обеспечения. Консольное приложение на C# / .NET 8: студенты курса, рубрикатор, оценки, взвешенный итог и экспорт ведомости.

Первая работа («ВышКат») сохранена в `VyshKat.sln`. Вторая работа находится в **`Pos.sln`** и проектах `Pos.*`.

## Запуск

Нужен .NET SDK 8. Команды выполняются из корня репозитория:

```sh
dotnet build Pos.sln --configuration Release
dotnet test Pos.sln --configuration Release
dotnet run --project src/Pos.Console
```

Если в Windows `dotnet` сообщает, что SDK не найден, хотя он установлен в пользовательскую папку, можно вызвать его напрямую:

```powershell
& "$env:LOCALAPPDATA/Microsoft/dotnet/dotnet.exe" run --project src/Pos.Console
```

В меню выбирается номер действия. Студенты и критерии выбираются по номерам из показанного списка; внутри модели используются `Guid`. Дробные числа принимаются с точкой и запятой. Повторное выставление по той же паре «студент — критерий» исправляет оценку, отмена удаляет её. Неверный ввод выводит сообщение и возвращает в меню. Конец входного потока завершает работу.

Хранилище в памяти, для одного курса и одного процесса. После выхода данные исчезают. CSV сохраняет итоговую ведомость, а не резервную копию курса. Импорт, редактирование и удаление студентов/критериев не реализованы; для обязательного сценария они не нужны.

## Демонстрация

```sh
dotnet run --project src/Pos.Console -- --demo results.csv
dotnet run --project src/Pos.Console -- --complete --demo complete-results.csv
```

Демонстрация создаёт двух студентов и два критерия, выставляет оценки, печатает списки, оценки, итоги и средний балл, затем экспортирует CSV:

| Студент | ДЗ (максимум 10, вес 40) | Экзамен (максимум 100, вес 60) | Итог из 10 |
| --- | --- | --- | --- |
| Анна Иванова | 8 | 90 | 8,60 |
| Иван Петров | 6 | 70 | 6,60 |

Средний итог: 7,60. При повторном запуске нужно указать новое имя CSV: существующие файлы не перезаписываются. Без пути используется `pos-results.csv`.

Для ручной проверки: добавьте студента (1), два критерия (3), выставьте оценки (5), посмотрите итог (8), исправьте оценку (5), отмените её (7), снова посмотрите итог и выполните экспорт (9). Балл выше максимума и отрицательный балл должны отклоняться, сохраняя прежнюю оценку.

## Правила расчёта

Для каждого критерия балл делится на его максимум. Веса нормализуются по сумме, поэтому можно задавать как `0,4 / 0,6`, так и `40 / 60`:

```text
итог = 10 × Σ ((балл / максимум) × (вес / сумма весов))
```

Округление выполняется один раз, в конце: до двух знаков, половины от нуля (`AwayFromZero`). Используется `decimal`.

- Обычный режим: отсутствующая оценка даёт нулевой вклад; вес критерия остаётся в знаменателе. В ведомости отмечаются пропуски.
- `--complete`: итог доступен только при оценках по всем критериям. Выставленный ноль считается оценкой. Для неполных данных CSV содержит пустой итог и объяснение.
- Без критериев итог не определён. Без студентов ведомость пуста.
- Добавление критерия сразу влияет на следующий расчёт. Итог не хранится отдельно и не может устареть после исправления или отмены оценки.
- Максимум и вес положительны и не превышают 1 000 000; балл лежит в `[0, максимум]`. Ограничение параметров защищает арифметику `decimal` от переполнения.

## DDD

Общий язык отражён в именах: `Student` — студент, `Criterion` — критерий, `Evaluation` — оценка, `Course` — курс, `FinalScoreService` — расчёт итога.

| Элемент | Роль и ответственность |
| --- | --- |
| `Course` | Корень единственного агрегата курса: владеет студентами, рубрикатором и оценками. Все изменения проходят через него. |
| `Student`, `Criterion` | Entity с идентичностью `Guid`. Два студента с одинаковыми именами остаются разными студентами. Названия критериев уникальны без учёта регистра и крайних пробелов. |
| `Evaluation` | Неизменяемый Value Object с равенством по значениям: студент, критерий, балл. Отдельного ID нет. Исправление заменяет значение для пары идентификаторов. |
| `EvaluationFactory` | Проверяет принадлежность студента и критерия курсу и диапазон балла до создания оценки. |
| `FinalScoreService` | Domain Service: итог требует рубрикатора и набора оценок, поэтому не принадлежит одной оценке или студенту. |
| `ICourseRepository` | Порт получения и сохранения агрегата; реализация хранилища снаружи домена. |

Граница агрегата выбрана для небольшого однокурсового приложения: проверка ссылок и изменение оценки происходят в одной модели. Внутренние коллекции не выдаются для изменения, свойства сущностей доступны только для чтения. Нельзя добавить оценку в обход методов курса. Невалидная попытка исправления не удаляет прежнее значение. При росте до множества курсов и параллельных пользователей границы хранения и конкурентные изменения потребуют отдельного решения.

## Архитектура Ports and Adapters

```text
Pos.Console ────────────> Pos.Application ─────> Pos.Domain
     │                          ▲
     └─> Pos.Infrastructure ────┘
```

- `src/Pos.Domain`: сущности, Value Object, инварианты, фабрика, стратегии и Domain Service. Нет зависимостей от других проектов, консоли, файлов и DI.
- `src/Pos.Application`: сценарии в `AssessmentFacade`, порты `ICourseRepository` и `IResultExporter`, строка отчёта `ResultRow`.
- `src/Pos.Infrastructure`: адаптер хранилища `InMemoryCourseRepository` и адаптер экспорта `CsvResultExporter`.
- `src/Pos.Console`: входной адаптер, разбор ввода, отображение и composition root в `Program.cs`.
- `tests/Pos.Tests`: тесты домена, сценариев и CSV.

Ссылки между отдельными `.csproj` закрепляют направление зависимостей. Только composition root знает конкретные реализации адаптеров. `Microsoft.Extensions.DependencyInjection` собирает репозиторий, экспортёр, выбранную стратегию, сервис расчёта, фасад и консоль. Singleton-хранилище сохраняет один курс на протяжении сеанса.

## Паттерны

| Группа | Паттерн | Где и зачем |
| --- | --- | --- |
| Порождающий | Factory | `EvaluationFactory.Create`: единая точка создания оценки, совмещающая проверку ссылок на текущий курс с проверкой диапазона. Используется и для первой оценки, и для исправления. Это простая фабрика, а не иерархия Factory Method. |
| Структурный | Facade | `AssessmentFacade`: консоль вызывает сценарии, не координирует репозиторий, расчёт и экспорт. Инварианты остаются в модели. |
| Поведенческий | Strategy | `IFinalScoreStrategy`: обычный расчёт с нулевыми пропусками или расчёт только полной ведомости. Выбор в composition root по `--complete`, без условий в доменных сущностях. |

## Экспорт и тесты

CSV: UTF-8 с BOM, разделитель `;`, десятичная точка. Поля: `student_id`, `student_name`, `score`, `status`. Текст заключён в кавычки, внутренние кавычки удваиваются. Начальные символы формул экранируются апострофом для открытия в табличных редакторах. Ошибки доступа к файлу сообщаются пользователю; существующий файл сохраняется.

Тесты проверяют границы балла, неизвестные ссылки, параметры и названия критериев, сохранность прежней оценки при ошибке, пересчёт после исправления/отмены/добавления критерия, округление, пустой рубрикатор, отличие нуля от пропуска, сценарий через фасад и корректность CSV.
